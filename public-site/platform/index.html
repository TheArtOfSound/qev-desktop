QEV · Developer evaluation

Capture, seal, and inspect a synthetic record.

The hosted gateway is an authenticated, single-tenant operator test. It supports synthetic evaluation; it is not an open customer workspace.

What is available

Signed webhook capture, encrypted evidence packages, passphrase verification, and persisted records are available to the authorized operator using a gateway token. The public health response reports liveness and scope; it does not grant private access.

Choose your first step

  1. A private file or note: use the local browser vault. No account, upload, or gateway is required.
  2. A developer evaluation: inspect the public health response and gateway guide. Private API requests require a gateway bearer token; signed webhooks require the configured signature.
  3. Real team data: agree a pilot and deploy a customer-controlled gateway in the customer's environment. Decide who owns the keys, which events may be captured, and how recovery will be tested.

Hosted evaluation limits

Do not submit confidential customer records. The operator evaluation processes synthetic plaintext on Qira's host before sealing. Customer-controlled deployments keep their plaintext and package keys on the customer's host. The hosted test does not establish independent source truth, security certification, enterprise availability, or a validated business outcome.

The evaluation remains in shadow mode. It cannot enable gate mode or watched host folders. Private reads, uploads, settings and admin routes require authentication. Bodies are limited to 1 MiB.

API entry points

  • GET /platform/v1/health — public liveness and evaluation scope.
  • GET /platform/v1/preflight — authenticated readiness and local cryptographic checks.
  • POST /platform/v1/webhooks/ci — configured HMAC signature.
  • POST /platform/v1/flows/{flow_id}/complete — authenticated package sealing.
  • POST /platform/v1/packages/{package_id}/verify — authenticated verification with the correct passphrase.

Never put a token or passphrase in a URL or public inquiry.

Accounts and the older workspace

The local vault requires no account. A gateway token is an automation credential for the agreed deployment; it does not create another consumer login. The older chat/voice workspace remains unavailable and is separate from this capture gateway.
