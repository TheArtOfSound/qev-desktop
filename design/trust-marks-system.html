Trust marks: a system for claims that state their own limits

QEV already says the right thing in prose — “badges link to scoped certificates, never ‘this whole company is secure’.” Its interface didn’t have a component that enforced it. This is that component, plus the tokens it needs.

2026-07-29 landing/trust-marks.css WCAG 2.2 AA verified, both themes
The thesis

A verdict is a claim plus its scope

The audit found three security claims that were false and two verification recipes that didn’t work. None of that came from bad cryptography — the cryptography was sound. It came from claims that had drifted loose from what was actually checked.

So the system’s one rule: a trust mark cannot render without a scope. The scope isn’t fine print, it’s a required child element. Omit it and the component visibly fails in development rather than shipping a bare green tick.

The anti-pattern

✓ Secure

Proves nothing, scopes nothing, and survives contact with reviewers only until someone asks “secure against what?” This is the badge QEV’s own trust page argues against.

The component

Site manifest signature valid Ed25519 over 75 files. Proves the signer held the private key — not that the key belongs to who you think.

Same information density, but the limit travels with the claim. The scope line is monospace because in this product the factual half is always machine-derived.

StatesWCAG 1.4.1

Four states, none carried by colour alone

Each state has a distinct glyph shape as well as a hue, so the system survives greyscale, colour-blindness, and Windows forced-colors mode. The fourth state is the one the product was missing.

  • Verified — the check ran and passed 75/75 file digests matched the signed manifest.
  • Caution — passed, but narrower than it looks Bundle authenticated with HMAC-SHA256. Shared-secret authentication, not a public-key signature: anyone holding the key can forge it.
  • Failed — the check ran and did not pass Manifest signature did not verify over the canonical bytes.
  • Not checked — no verdict was produced No third-party security audit has been performed. This is an absence of evidence, not a failure — and the product had no way to say it.

“Not checked” earns a state of its own because every page that lacked it had to choose between implying a check had happened and saying nothing. Both are worse than a dashed grey circle.

Type

Monospace is the vernacular, not the code font

This product’s factual claims are digests, manifests, exit codes and verdicts. Monospace carries every one of them; the sans carries prose and persuasion. The split is semantic — if a line asserts something checkable, it is set in mono.

Target sizeWCAG 2.2 · 2.5.8

The hardest control to tap was the one explaining the cryptography

At 375 px the audit measured 17 controls below the 24 px minimum. The worst were the eight “what is this?” buttons — 15 px tall — which are exactly how a non-technical person learns what “secret number” and “scramble code” mean.

Applied

The audit’s own verdicts, rendered in the system

The real test of a trust language is whether it can state bad news as fluently as good. These are actual findings, in the component:

  • Vault round-trip is byte-exact 227 chars incl. emoji, CJK, backslashes, trailing whitespace. XChaCha20-Poly1305 + Argon2id, memlimit 96 MiB as documented.
  • KDF-downgrade attack rejected memlimit clamped to 8–256 MiB. An attacker cannot rewrite a vault to make offline cracking cheap.
  • Generated passphrase strengthened to ~58 bits Was 180 words, all a–e, ≈36.6 bits. Now the EFF long list: 7776 words, ≈58.3 bits — 3.5M× harder. Still weaker than a phrase you invent yourself.
  • Public challenge reveal is overdue reveal_at 2026-04-21, still pending at 2026-07-29 — 98 days. Bundle authentication is HMAC, unverifiable by third parties today.
  • Desktop, chat and relay behaviour Not verified. Would require installing unsigned, un-notarized binaries and bypassing Gatekeeper. Declined.

Tokens and components ship as landing/trust-marks.css. Contrast ratios computed with the WCAG 2.x relative-luminance formula against each token’s actual ground. Nothing here is loaded from a third party.
